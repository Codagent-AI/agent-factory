# Decisions

| Step | Decision | Alternatives considered | Decision-bearing |
| --- | --- | --- | --- |
| PR review | Task PRs close their issue on merge with exactly one `Closes #N` set by `annotate-chore-pr.sh`. | `Refs` with no closing keyword, as the fix spec states: rejected by Paul. Rely on the body from `finalize-pr`: rejected because it is not deterministic. | yes |
| propose | Verdict: go with caveats (strict triage gate; Bug/Feature parity). | No-go (fold chores into Bug or Feature): rejected because Bug triage and TDD and Feature definition both misfit maintenance work. | yes |
| propose | Tasks reach Owner=factory only through the existing Ready handoff (writer author) or `factory-assign`. No automatic routing rule. | Auto-route maintainer-authored Tasks like Bugs: rejected because the issue does not ask for it and it widens unattended intake. | yes |
| propose | Execution mode is `host` only for the new kind. | Docker and host like fix: rejected for now because the live service runs fixes on the host and a task sandbox would add an image and doctor group with no user. | yes |
| propose | Enabled by the presence of a `[task]` shared section (like `[feature]`). The committed `config/codagent.toml` gains `[task]` and `[routing] task_type`. | Always enabled like fix: rejected because it would change behavior for existing configs. Leave `[task]` out of codagent.toml: rejected because the acceptance criteria expect live admission. | yes |
| propose | Fix-sized default limits (900 s inactivity, 7200 s execution, 10800 s total). Sonnet-class lead in `[task.defaults]`. | Feature-sized limits: rejected because tasks must be small enough to review as one PR. | no |
| propose | `chore:` PR title is enforced by a factory-side retitle step after `builtin:core/finalize-pr`. Commits are asked to use `chore:` by prompt. | Add a title parameter to Agent Runner finalize-pr: rejected because it is outside this repository. | yes |
| propose | Reconciliation policy is settle-on-open-pr, and the review loop uses `factory-review/1`, both as for fix. | Feature-style resume from own branch: rejected because tasks have no definition checkpoints. | no |
| propose | Task triage also declines work that needs changes outside the target repository, mirroring fix triage. | Omit: rejected because the factory cannot deliver cross-repository changes in one claim. | no |
| propose | Spec capabilities: new `factory-task-intake`, `factory-task-execution`, `factory-task-reporting`; modified `factory-routing`, `factory-pull-request-lifecycle`, `factory-watch-dispatch`, `factory-operations`. | A single `factory-task` capability: rejected to match the existing per-kind intake, execution, and reporting split. | no |
| proposal-review | PR-1 applied: added a bounded-choice rule. Triage accepts evidence-based choices the issue delegates, such as fix-or-baseline and a measured threshold, when the issue or repository bounds them and runtime behavior is unchanged. Added a toolchain-versus-release-configuration boundary and a per-issue fit check for agent-factory#74, agent-validator#174 (no removal of published entry exports), and agent-evals#53 (the Node version must come from repository evidence, otherwise `needs-input`). | Keep the strict "decline open threshold decisions" rule: rejected because it would decline #74, the first motivating Task. Edit the issues instead: rejected because that is outside this change. | yes |
| proposal-review | PR-2 applied: on task claims, review rounds enforce task scope on every requested change and on the round's diff. Out-of-scope feedback records `needs-input` routed to Bug or Feature. This uses the review file's existing `kind`, keeps the contract `factory-review/1`, and leaves fix and feature review unchanged. Added `factory-review-execution` as a modified capability. | A separate `factory-task-review/1` contract: rejected as unnecessary because the review file already carries `kind`. Rely on intake triage only: rejected because reviewers could widen scope after the gate. | yes |
| proposal-review | PR-3 applied: new or tightened checks and CI jobs count as developer-visible. The workflow records a positive and a negative exercise for each gate (a scratch violation, reverted, with the final clean-tree gate as backstop), mandatory when the issue states a rejection criterion. `test-flows` stays conditional for other user-visible tooling. Docs and pure refactors skip both. | Make `test-flows` unconditional: rejected as wasteful for docs and refactors. Exercise gates only when the issue names a criterion: rejected because a new gate that never fails is the main risk. | no |
| spec | Shared lifecycle parity (slots, status-edit correction, pre-suite failure, closure exemption, cleanup, retention, deploy Validator skip, audit) is stated once as a `factory-task-execution` requirement that includes task claims wherever fix and feature claims are named. The `factory-claim-lifecycle` blocks and the other `factory-operations` blocks are not rewritten. | Modify every block that names "fix or feature": rejected because it touches about ten large blocks for a one-word change and invites copy drift. | no |
| spec | A threshold delegated to the work meets the issue's target when the repository meets it. Otherwise it is set at the measured baseline, never looser, and the gap is stated. | Pick any value between baseline and target: rejected as unbounded. Decline whenever the target is not met: rejected because it contradicts the issue's "measure before fixing the threshold". | yes |
| spec | A new gate that still does not fail on an introduced violation after one repair makes the attempt `failed` before any push. | Deliver with a warning: rejected because a gate that cannot fail is the defect PR-3 guards against. | no |
| spec | A `chore:` title that cannot be corrected after finalize is recorded in evidence and does not change the `pull-request` outcome. | Fail the attempt: rejected because the PR and CI are already good and the title is cosmetic. | no |
| spec | A task review round that meets an out-of-scope request implements nothing, pushes nothing, and posts no replies, then returns `needs-input` routed to Bug or Feature. A writer's reply (withdraw or narrow) admits a new round. | Implement the in-scope comments and stop only for the rest: rejected because it leaves a partly answered round and diverges from the existing conflicting-request rule. | no |
| spec | Task review rounds do not merge the base branch, as for fixes. | Merge like features: rejected because tasks have no acceptance evidence to protect and the fix rule is simpler. | no |
| spec | The acceptance comment reads `Task inputs accepted and frozen.` and triage-decline comments state that no branch was pushed. | Reuse the fix wording: rejected because the comment would misname the kind. | no |
| spec | Operator skills (`factory-assign --apply task`, `factory-status`) and the docs are specified as `factory-operations` additions, because the skills live in this repository under `.claude/skills/`. | Leave them unspecified: rejected because the issue lists them in scope. | no |
| design | Add `task` as a third `PullRequestKind` (registered last) on the generic handler. Only the remaining kind literals are touched: supervisor contract map, watch PR-READY kinds, readiness no-target diagnostic, non-writer handoff comment, decline "No branch was pushed.", host banner, and assign skill. | A dedicated TaskHandler: rejected as duplication of the generic lifecycle. | no |
| design | New `factory-task-v1.0.yaml` instead of parameterizing `factory-fix`. Shared mechanics come from generalized `record-triage.sh` (optional `contract`, `accept_field`, `decision_path`, with fix defaults unchanged) and reused `record-outcome.sh` and `check-contract.sh`. | A shared fix/task workflow with `skip_if` branches: rejected because it risks the `factory-fix/1` contract. | no |
| design | `chore:` is enforced deterministically. `normalize-chore-commits.py` rewrites unpushed linear commit subjects with identical trees before finalize, and `annotate-chore-pr.sh` retitles over REST after finalize. | Prompt-only enforcement: rejected as unreliable. Add an Agent Runner finalize title parameter: rejected because it is outside this repository. | no |
| design | A gate exercise is agent-run but script-verified: `check-gate-exercises.py` requires a positive exit of 0, a non-zero negative exit for every triage-named gate, and a clean tree. | Agent self-report only: rejected because a skipped exercise could pass. | no |
| design | Review-round diff scope combines the deterministic `task-scope-floor.py` (openspec/specs, release/publish/deploy workflows, CODEOWNERS) with a lead judgment step inside `factory-implement`, gated by a new `task_scope` param (default false). In the initial attempt the floor is only review evidence, because triage is the intake gate. | Agent judgment only: rejected because it can miss release edits. A floor stop in the initial attempt too: rejected because it adds an unspecified outcome path. | no |
| design | `factory-review/1` is kept. The task branch keys off `review.json` `kind`, and task rounds are not base-merged because `base_head` is written only for features. | A new `factory-task-review/1` contract: rejected as unnecessary migration. | no |
| design | Config parsing is generalized (`_host_kind_local_config`, `_optional_kind_shared_config`) for both feature and task, to avoid copy-paste in a repository about to gain duplication gates. | Copy the feature parser: rejected because of duplication. | no |
| test-plan | Automated tests follow the existing practice. Packaged workflows are covered by structural assertions, `agent-runner -validate`, and subprocess tests of every script, not by stub-agent execution. E2E covers three `tick` journeys mapped to the issue's three acceptance criteria. | Execute the task YAML under the real Runner with stub agents in CI: rejected because no harness exists and the Runner may be absent. | no |
| test-plan | Routing gets no new INT or E2E obligation, because `routing.py` is unchanged and already treats Task-typed issues as untyped. Unit and spec scenarios in the existing routing tests cover it. | A routing integration test: rejected as duplicating unchanged behavior. | no |
| test-plan | The acceptance envelope authorizes up to three real host task attempts (decline, lint-plus-gate accept, out-of-scope review round), about $15, against a local scratch repository with a local bare origin and a `gh` stub. No real GitHub effects. | Stand-in only: rejected because triage and scope judgment are prompt-driven and only real sessions exercise them. | no |
| test-plan | HT-001 is the first live Task (agent-factory#74) after deploy, because it needs Paul's deploy authority and real GitHub effects. | None: rejected because the live assignment and PR are irreversible, outward-facing acts. | no |
| approach-review | AR-001 applied: a binding pre-push guard (`factory-task-guard`, scope floor plus lead judgment) checks the complete initial-attempt diff from the recorded target commit after address-findings and the final validator. A crossing returns `needs-input`, nothing pushed. Added as spec requirement "Guard every pushed head against the task boundary", plus design, INT-003 ordering, and INT-004 script cases. | Keep the floor advisory: rejected because an implementor or finding repair could push an excluded edit. Return `failed` instead: rejected because a crossing is a scope decision for a human, matching the review-round stop. | no |
| approach-review | AR-002 applied, keeping the builtin: `builtin:core/finalize-pr` stays, because the issue names it, and the Runner rejects `ci_fix_cycles` < 1 (`resolveMaxParam`). A post-finalize guard re-checks the complete diff, re-exercises any gate whose files CI repair touched, and lists non-`chore:` subjects. A crossing or unconfirmed gate returns `failed` with the PR open. Specs: commits before finalization are normalized, CI-repair commits are recorded (not rewritten), and the review-round spec adds post-finalize `failed`. | Replace the builtin with a factory-owned push and CI loop: rejected because it contradicts the issue's named finalizer and duplicates CI semantics. Disable CI repair: impossible because the Runner requires at least one cycle. | yes |
| approach-review | AR-003 applied: gate proof now requires the triage-named command for both runs, a saved planted patch and both logs, and an independent lead verdict whose verbatim diagnostic appears only in the negative output and that confirms the issue criterion. `check-gate-exercises.py` enforces all of it. Tests cover an unrelated non-zero failure and a different command. | Exit codes only: rejected because an unrelated error would count as proof. | no |
| approach-review | AR-004 applied: the migration plan and HT-001 add a pre-merge audit of Ready Task cards in all fix targets. Each one other than agent-factory#74 is moved to Backlog or approved before `[task]` goes live. | An enablement cutoff in code (an admission date or explicit assignment gate): rejected as new permanent behavior for a one-time rollout risk. | no |
| tasks | A single implementation task covers the whole change, scoped in seven parts (config, kind, literals, workflow, review rounds, operations, tests). It names the approach-review rows as overriding earlier design rows, and gives "Done when" criteria mapped to the issue's acceptance criteria and the test-plan obligations. | Several tasks: rejected because the step requires exactly one. | no |
